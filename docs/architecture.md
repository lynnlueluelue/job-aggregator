# 考编公告聚合站 · 架构文档

> 说明：本文描述本 skill 生成的"个人考编公告聚合站"整体架构。文中以 **广东（深圳/广州/东莞）** 渠道作为已收录示例（`scripts/region_data.py` 的 `PROVINCE_CHANNELS`），其他省份默认只启用全国通用渠道，用户可在生成的 `config.py` 中按同样格式补充本省门户。

## 一、项目概述

个人求职情报聚合站：自动抓取 **目标省份/城市的事业单位、国企央企、高校** 招聘公告，按用户画像做"能否投递"自动核对与硬排除，支持考试追踪、手动标记与桌面通知。本地离线运行，不依赖云端。

**用户画像**（驱动筛选，由问卷生成，见 `profile.json`）：年龄 / 学历 / 政治面貌 / 专业大类与全称 / 目标单位类型 / 校招社招偏好 / 附加关键词。

## 二、技术栈

| 组件 | 选型 | 说明 |
|---|---|---|
| 后端 | Python 3.12 + Flask | 本地服务 + 数据接口 |
| 抓取 | requests + BeautifulSoup(lxml) | 静态页解析 |
| 附件解析 | zipfile 免依赖（xlsx/docx）+ pdfplumber（pdf） | 岗位表专业补查 |
| 前端 | 单文件 index.html（原生 JS） | 无框架，直接静态托管 |
| 通知 | plyer | Windows 桌面弹窗 |
| 数据 | data/*.json | 本地文件存储 |

## 三、系统架构与数据流

```
渠道列表 → fetch_list(分页/API) → 详情抓取 fetch_detail
        → 内容判定 content_judge(kind: job/notice/result)
        → 报考条件核对 screen_item(年龄/党员/专业/择业期)
        → 附件岗位表兜底 → 硬排除 → 去重排序
        → data.json → Flask /api/data → 前端渲染
```

- **定时刷新**：每 3 小时一次；有新公告弹桌面通知
- **通知范围**：仅第一梯队（tier 1）渠道的新公告触发桌面通知
- **渠道容错**：某渠道抓取失败自动保留旧数据，不回退

## 四、信息源渠道

## 五、分类与评分

- **score_item**：标题关键词加权（置顶词 +3 / 普通词 +1），决定排序与"新公告"通知
- **classify_item**：投递方式（考试/直接投递/结果公示）、单位类型（事业单位/高校/国企/央企）、地区、中小学岗、博士岗、校招/社招标签
- **content_judge**：正文招聘信号分 − 噪音分 × 1.5 → 判 `job` / `notice` / `result`
- 国聘/24365 为岗位级平台，直接判 `job`

## 六、报考条件自动核对（核心，screen）

依据 `USER_PROFILE` 对每条 job 公告核对，产出 `ok / reasons`：

| 条件 | 规则 |
|---|---|
| 招聘对象 | 含择业期/仅应届/社招 → 仅标签，不排除 |
| 年龄 | 提取年龄上限（含"本科/硕士/博士分档"、"放宽至"、"出生日期后出生折算"），按用户学历档取上限，**低于用户年龄 → 排除** |
| 党员 | 需党员 → 排除（用户非党员）；党员优先 → 保留降序 |
| 专业 | 四态：**对口**（命中 `MAJOR_FIT_KEYWORDS` 或"专业不限"）/ **相关**（`MAJOR_RELATED_KEYWORDS`）/ **不符**（仅当语境词 + `UNFIT_MAJOR_EXAMPLES` 命中）/ **未标注**；附件岗位表尽力解析，解析不出标"未解析"不误杀 |
| 学历 | 标题含"博士"→ 博士岗排除（开关）；**高校人才网增强**：职位列表页实际含用户学历可投档则解除排除、全部高于用户学历才保留 |

**高校人才网职位列表页结构化信号**：gxj 职位列表页每行职位含**职位名（内嵌学历）**与**需求专业**两列，比正文文本更精准，按以下逻辑覆盖 ②专业 / ③学历 判定：

- **学历**：职位列表含用户可投档（学历 ≥ 用户学历）→ 解除标题含"博士"导致的博士岗排除；全部职位学历均高于用户 → 保留博士岗排除。
- **专业**：需求专业命中 `MAJOR_FIT_KEYWORDS` → 定"对口"；命中 `MAJOR_RELATED_KEYWORDS` → 定"相关"；两者都无且需求专业以无关专业为主 → 定"专业不符"排除。
- 专业定为对口/相关时同时**清除正文层"专业不符"误判**、恢复 `ok=True`、解除标题层误杀；**需党员、年龄为独立条件，不被覆盖**。
- 仅在"可能有改善空间"时抓取职位列表（被博士岗/专业不符排除、专业未标注/未解析），减少对 WAF 站的高负载请求。

硬排除结果并入 `blocked`（前端默认隐藏，可"显示已排除"查看原因）。

## 七、去重

- `fingerprint`：标题+日期 MD5
- `norm_dedup_key`：跨渠道识别同源公告，保留得分高/官方渠道者

## 八、前端功能

- **Header**：白底深字精简布局，meta 行（更新时间/总条数/刷新频率）并入按钮行
- **封面 Hero**：渐变背景，深色文字 + 青绿高亮词"体制内机会"，右侧白色圆角卡片"情报概览"（4 格梯队统计 + 高分精选 + 更新时间绿点），底部 ↓ 下滑箭头平滑滚动进入列表；响应式适配移动端
- **书签栏**（无法抓取渠道常驻入口）：默认展开、横向轮播卡片，带 favicon 图标 + 名称 + 域名
- **筛选面板**：默认展开为横排下拉；一级（常显）自定义添加 / 求职追踪 / 标记 / 发布时间 / 单位类型；二级（"更多条件"）排除开关、投递方式、校招社招、地区、招聘对象、年龄上限、党员要求、专业对口、已追踪列表、条件核对说明
- **刷新弹窗**：打开/刷新网页时弹窗显示上次自动刷新时间，并询问是否立即刷新
- **排除开关**：中小学教师岗 / 博士岗 / 专业不符 / 政策新闻 / 显示已排除
- **求职追踪**：添加参加考试名 → 只显示对应聘用/录用结果公示
- **自定义添加**：粘贴公告链接即入库并自动分类核对
- **列表**：第一梯队合并为一个卡片，第二梯队及以后按梯队→渠道分组；白底圆角卡片、tier 色圆圈、关键词高亮、彩色胶囊标签；右侧"去投递/标记完成"文字按钮，复制原网址/删除走右键菜单
- **搜索**：右下角圆形悬浮搜索按钮，点击弹出搜索面板
- **加载反馈**：骨架屏、刷新按钮 loading 态、轮询更新时间后即时重绘
- **统计条**：彩色胶囊徽标行（显示数/总数、已排除、政策新闻、隐藏公示、已删去）

## 十、运行与部署

```powershell
# 1. 生成站点（问卷 → 配置渲染 → 自检）
python <skill路径>/scripts/questionnaire.py
python <skill路径>/scripts/generate.py
python <skill路径>/scripts/privacy_check.py     # 可选，确认无个人数据残留
python <skill路径>/scripts/site_verify.py       # 可选，启动冒烟自检

# 2. 安装依赖并启动（需 utf-8 环境变量，避免中文报错）
pip install -r requirements.txt
$env:PYTHONIOENCODING="utf-8"
python server.py   # 访问 http://127.0.0.1:8765
```

- 手动刷新：前端按钮或 POST `/api/refresh`；关键配置（渠道/关键词/画像）集中在 `config.py`，改分类逻辑需递增 `CLASSIFY_VERSION` 触发全量重判。

## 十一、已知限制与后续方向

- 24365 详情页需登录（用标题+学历核对）、部分本地站偶发限流、个别官网 SSL 不通、部分平台为 JS 站（均转书签）
- 博士岗检测：**高校人才网已用职位列表实际岗位判定**；其余渠道仍为标题级检测
- 各省专属渠道依赖人工补充：`scripts/region_data.py` 只收录了可信入口，其他省份用全国通用渠道 + 在 config.py 按注释格式自行添加本省门户
